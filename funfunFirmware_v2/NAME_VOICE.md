# v2 — 아이 이름을 소리로 읽기 (절차)

키링을 대면 `[김용민] [출석 완료] [오] [포인트]` 처럼 **이름부터** 읽게 한다.
이름은 미리 구울 수 없어서(교회마다·아이마다 다르다) **서버가 만들어 두고, 기기가
한가할 때 받아 microSD 에 써 둔다.** 태깅하는 순간에는 받지 않는다 — SD 에서 바로 튼다.

본보기는 이미 도는 두 길이다. 새로 지어내는 것이 거의 없다.

| 이미 있는 것 | 이름 소리에서 |
|---|---|
| 서버 `talentPhoto.prepareNameImages` — 등록·이름 변경 때 이름 그림을 미리 만든다 | `talentVoice.prepareNameVoice` — 같은 자리에서 이름 소리를 미리 만든다 |
| 파일 이름에 내용이 들어가 "있다 = 최신" (`nm-<base64url>-240.565`) | `<해시>.wav` — 이름이 바뀌면 해시가 바뀌어 새로 받는다 |
| `/roster` 의 `img` 칸 → `/photo/device/<img>` | `/roster` 의 `snd` 칸 → `/voice/device/<snd>.wav` |
| 펌웨어 `photoPrefetchIdx` — 대기 때 한 장씩 받아 PSRAM 에 | 같은 자리에서 한 개씩 받아 **SD** 의 `/09/` 에 |
| 이름 바뀌면 서버가 `{"state":"roster"}` 를 민다 | 그대로 — 그 신호로 이름 소리도 다시 훑는다 |

---

## 0. 먼저 정할 것 두 가지

### 0-1. 파일 꼴 — mp3 가 아니라 **WAV 를 권한다**

v2 는 일부러 WAV 만 튼다(`sound.h` 머리말 — 디코더가 없고 코어의 `SD`·`ESP_I2S` 만 쓴다).
이름 소리도 WAV(PCM 16비트 · 모노 · 22050Hz)로 받으면 **트는 쪽은 한 줄도 안 바뀐다.**

- 크기: 이름 한 개 0.7초 남짓 → 30KB 쯤. 400명이면 12MB — SD 에서는 문제가 아니다.
- 받는 양: https 로 30KB 는 한 번에 1초 안쪽. 대기 때 한 개씩이라 부담이 없다.
- mp3 로 하려면 디코더(libhelix · ESP8266Audio 따위)를 붙이고 재생 일꾼을 둘로 갈라야
  한다. 얻는 것은 SD 용량(이미 넉넉하다)과 받는 양(이미 작다)뿐이다.

→ 서버는 **WAV 로 만든다.** (mp3 가 꼭 필요해지면 서버에서 꼴만 바꾸고 기기에 디코더를 더하는
  단계를 따로 둔다.)

### 0-2. 목소리 엔진 — 서버(리눅스 Docker)에는 맥의 `say` 가 없다

지금 고정 토막은 맥 `say -v Yuna` 로 구웠다. 서버에서는 다른 엔진을 써야 한다.

| 엔진 | 장점 | 단점 |
|---|---|---|
| **Google Cloud Text-to-Speech** (권함) | `ko-KR` 목소리가 여럿. **LINEAR16 · 22050Hz 를 그대로 내준다** — ffmpeg 이 필요 없다. 이미 GCP 서비스 계정이 있다. 이름 몇 글자라 무료 한도 안 | GCP 프로젝트에서 API 를 켜야 한다 |
| 네이버 CLOVA Voice | 한국어가 가장 자연스럽다 | 유료 · 키 따로 |
| 맥에서 굽고 서버에 올리기 | 고정 토막과 목소리가 같다 | 아이를 등록할 때마다 사람이 맥을 돌려야 한다 — 자동이 아니다 |

★ **목소리가 섞이는 문제** — 이름만 Google 목소리, 나머지는 Yuna 면 한 문장 안에서 사람이
바뀐다. 그래서 **5단계에서 고정 토막도 같은 엔진으로 다시 굽는다**(서버가 만들어 기기가
받아 가게 하면 SD 를 빼서 복사하는 일도 없어진다).

## 1단계 — 서버: 이름 소리 만들기 (`funfunServer/talent/talentVoice.js`) ✅ 2026-11-06

> **만든 대로 적으면** (아래 계획과 다른 데):
> - 자리는 `uploads/.talent-voice/` — 볼륨은 사진과 함께 쓰고, 점 폴더라 `/uploads` 공개 경로로
>   열리지 않는다(파일 이름이 아이 이름에서 나와 짐작할 수 있기 때문).
> - 키 재료에 목소리·속도도 넣었다 — `.env` 에서 목소리를 바꾸면 리더가 저절로 새로 받는다.
> - 옛 이름 파일은 이름 그림과 같은 규칙으로 **그냥 지운다**(같은 이름의 다른 아이 것이면 리더가
>   달라고 할 때 다시 만든다 — 2단계의 "없으면 그 자리에서 만든다").
> - 크기를 고정 토막(RMS 4200 쯤)에 맞추고 앞뒤 무음을 자른다.
> - 시험: `node scripts/selftest/name-voice.js` (run-all 에도 넣었다 · 구글을 부르지 않는다).
> - 옛 아이 채우기: `scripts/prepare-name-voices.js --dry` → `--all`.
> - ★ 켜기 전에 GCP 프로젝트(344114885235)에서 **Cloud Text-to-Speech API** 를 켜야 한다.

1. GCP 에서 **Cloud Text-to-Speech API** 를 켜고, 서버가 쓰는 서비스 계정에 권한을 준다.
   `.env` 에 `TALENT_VOICE=on`, `TALENT_VOICE_NAME=ko-KR-Neural2-A`(목소리), `TALENT_VOICE_RATE=0.95` 를 둔다.
   **꺼져 있으면 `snd` 칸을 싣지 않는다** — 기기는 지금처럼 이름 없이 읽는다.
2. 키 만들기:
   ```
   VOICE_VER = '1'                                   // 목소리·속도를 바꾸면 올린다 → 모든 기기가 새로 받는다
   voiceKey(name) = sha1(VOICE_VER + '|' + 읽는이름(name)).hex.slice(0, 8)   // 'a1b2c3d4'
   ```
   - 8자로 둔다 — FAT 에서 `a1b2c3d4.wav` 는 8.3 이름이라 긴 이름 지원에 기대지 않는다.
   - 해시 재료가 **이름 글자**라 동명이인은 한 파일을 함께 쓴다(같은 소리니 맞다).
3. 만들기: TTS 에 `audioEncoding: LINEAR16, sampleRateHertz: 22050` 으로 부탁한다.
   돌아온 WAV 의 머리(44바이트)가 **모노 · 16비트 · 22050** 인지 확인하고
   `uploads/talent-voice/<key>.wav` 에 쓴다. 앞뒤 무음이 길면 잘라 낸다(태깅 응답이 늘어진다).
4. `prepareNameVoice(name, prevName)` — `prepareNameImages` 를 부르는 **두 자리**
   (`TalentManager.js` 2645 · 3004 근처)에 나란히 건다. 기다리지 않는다(`.catch` 로 로그만).
   옛 이름의 파일은 다른 아이가 같은 이름을 쓰지 않을 때만 지운다.
5. 이 기능 전에 등록된 아이를 위해 한 번 도는 스크립트: `scripts/prepareNameVoices.js`
   (명단 전부를 돌며 없는 것만 만든다 · TTS 에 몰리지 않게 하나씩).

## 2단계 — 서버: 기기에 내주기 ✅ 2026-11-06

> **만든 대로 적으면**:
> - `GET /api/talent/voice/device/<키>.wav` (기기 키) → `audio/wav` · `Cache-Control: private`.
>   없으면 그 자리에서 만들고, 만들지 못하면 **503**(리더는 다음 바퀴에 다시 온다).
>   키 꼴이 아니면 400, 명단에 없는 이름·서버에서 꺼 둠은 404.
> - 교회 가르기: 키 → 이름 표를 **그 교회 명단으로만** 만든다(60초 들고 있고, 표에 없는 키가 오면
>   5초가 지난 표일 때만 다시 읽는다). 다른 교회 기기로 떠보면 파일이 있어도 404 다.
> - `/roster?snd=1` → 이름 줄마다 `snd`. 안 주거나 서버가 꺼져 있으면 칸이 없다.
> - 시험: `node scripts/selftest/name-voice-route.js` (run-all 에도 넣었다).
> - **펌웨어가 기억할 것**: 200 이 아니면 쓰지 말고 건너뛴다. 404 는 다음 이름표를 받을 때까지
>   다시 묻지 않아도 되고, 503 은 다음 바퀴에 다시 묻는다.

1. `GET /api/talent/voice/device/:key.wav` (헤더 `x-talent-key`, `requireDeviceKey`)
   - `key` 는 `/^[0-9a-f]{8}$/` 만 받는다 — 경로를 타고 나가지 못하게.
   - 파일이 있으면 `Content-Type: audio/wav` · `Content-Length` 를 붙여 그대로 보낸다.
   - 없으면 **그 키의 이름을 찾아** 그 자리에서 만들고 보낸다(미리 못 만든 것). 못 찾으면 404.
   - ★ 그 키가 **그 교회 명단의 이름**에서 나온 것인지 본다 — 다른 교회 아이 이름을 해시로 떠보지 못하게.
2. `/roster` 에 `snd` 칸 — **`?snd=1` 을 준 기기에만** 싣는다.
   CLAUDE.md '절대 잊지 말 것' 3번(`/roster` 응답을 키우지 말 것) 때문이다. 옛 펌웨어는 안
   주므로 응답이 그대로다. 이름이 없는 줄에는 싣지 않는다.
3. 이름이 바뀌면 이미 `{"state":"roster"}` 가 기기로 간다 — 따로 할 것 없다.
4. 확인:
   ```bash
   curl -s -H "x-talent-key: $KEY" "$SERVER/api/talent/roster?px=240&all=1&snd=1" | jq '.data[0]'
   curl -s -H "x-talent-key: $KEY" "$SERVER/api/talent/voice/device/a1b2c3d4.wav" -o /tmp/n.wav && afplay /tmp/n.wav
   ```

## 3단계 — 펌웨어: 받아서 SD 에 써 두기 ✅ 2026-11-06 (빌드만 · 기기에서는 아직)

> **만든 대로 적으면**:
> - `config.h` — `NAME_VOICE_ENABLE` · `NAME_VOICE_MAX`(1024) · `NAME_VOICE_BUF_MAX`(192KB) · `NAME_VOICE_BACKOFF_MS`(60초).
> - `sound.cpp` — 일꾼이 켤 때 `/09` 를 훑어 키 목록(PSRAM)을 만들고 남은 `.tmp` 를 지운다. 쓰기는
>   한 칸짜리 자리로 넘겨받아 **줄이 빌 때만** `.tmp` → `.wav` 로 쓴다. 본 고리는 `soundNamesReady` ·
>   `soundHasName` · `soundStoreBusy` 로 목록만 보고 SD 는 건드리지 않는다.
> - `main.cpp` — 이름표에 `&snd=1` · `RosterRow.snd`. 그림이 없어도 snd 가 있으면 줄을 담는다.
>   대기 중 **사진을 다 받은 뒤** 한 고리에 하나(`voiceGet`). SD 에 있는 키·앞 줄과 같은 키는 지나간다.
>   200 + 길이 맞음 + `soundWavOk` 일 때만 넘긴다. 404 는 다음 이름표까지 묻지 않고, 그 밖은 60초 쉬고
>   다음 이름으로(그 이름은 다음 이름표 — 10분 — 때 다시).
> - 시리얼 `i` 에 `[이름소리] SD 에 N개 · 이번에 받아 쓴 것 · 못 쓴 것` 이 붙는다.
> - 치우기(5번)는 아직 안 했다.

1. `RosterRow` 에 `char snd[9]` 를 더하고, 이름표 주소에 `&snd=1` 을 붙인다(`main.cpp` 1504).
   이름표 JSON 파싱에서 `snd` 를 읽는다(없으면 빈 값 — 서버가 꺼 둔 경우).
2. **SD 는 재생 일꾼만 만진다**는 규칙(`sound.cpp` 머리말)을 지킨다. 그래서 둘로 나눈다:
   - **본 고리(loop)** — 사진 미리 받기(`photoPrefetchIdx`, 3094 근처) 바로 옆에 `voicePrefetchIdx` 를
     하나 더 둔다. 대기 중 한 번에 **한 개만**: 그 키가 SD 에 이미 있는지 일꾼에게 묻고
     (`soundHasName(key)` — 일꾼이 켤 때 `/09/` 를 훑어 만든 목록을 본다),
     없으면 https 로 받아 **PSRAM 버퍼**(최대 64KB)에 담는다.
   - **재생 일꾼** — 버퍼를 넘겨받아(`soundStoreName(key, buf, len)`) `/09/<key>.tmp` 에 쓰고,
     다 쓰면 `/09/<key>.wav` 로 이름을 바꾼다. 쓰다 끊긴 반쪽 파일이 `.wav` 로 남지 않게 하려는 것이다.
     켤 때 남아 있는 `.tmp` 는 지운다.
3. 받기는 **태깅·사진보다 뒤**다. 키링이 대어지면 그 한 개를 마치고 바로 손을 뗀다.
   첫 부팅에 400명이면 400번 — 대기 중 몇 초에 하나씩이면 몇십 분이면 다 찬다.
   덜 찬 동안 그 아이는 이름 없이 읽힐 뿐이다.
4. 받은 WAV 의 머리를 확인한다(RIFF · PCM · 모노 · 16비트). 아니면 쓰지 않고 로그만.
5. 치우기(나중에 해도 된다): 이름표를 다시 받은 뒤 `/09/` 에 있는데 명단에 없는 키는
   한 바퀴에 몇 개씩 지운다. SD 가 넉넉해 급하지 않다.

## 4단계 — 펌웨어: 태깅할 때 이름부터 읽기 ✅ 2026-11-06 (빌드만 · 기기에서는 아직)

> 만든 것 — 아래 계획과 다른 데만 적는다.
> - 줄의 칸은 `char key[9]` 가 아니라 `uint32_t key` 다(목록과 같은 꼴 · 4바이트). 이름 토막은
>   `folder` 가 9 이고, 그때 파일이 `/09/<key 16진 8자>.wav` 다.
> - `rosterSndFor` 대신 `rosterRowFor(uid)` 하나로 줄을 찾아 사진(`img`)과 키(`snd`)를 함께 꺼낸다
>   (`rosterImgFor` 는 없앴다 — 부르는 곳이 `showNfc` 하나였다).
> - 이름을 읽는 때: 이름표에 그 카드(UID 또는 학번)가 있고 그 소리가 SD 에 있을 때.
>   서버를 못 불렀어도(`서버에 물어보지 못했어요`) 이름표로 누구인지 알아 읽는다. 서버가
>   `등록되지 않은 키링` 이라 한 카드만 뺀다(이름표가 아직 옛 것일 수 있다).
> - 이름 뒤 쉼은 `SOUND_NAME_GAP_MS`(150ms)로 따로 뒀다 — 서버가 이름 앞뒤 무음을 30ms 만 남겨
>   60ms 면 붙어 들릴 것 같아서다. 들어 보고 맞춘다. 끄는 스위치는 `SOUND_SAY_NAME`.
> - 시리얼은 `n` 이 아니라 **`a`** 다(`n` 은 이미 '대기 화면'). `i` 에는
>   `[이름소리] 이름표 N줄 가운데 M줄이 SD 에 있다` 가 붙는다.
> - 틀려는데 파일이 없거나 깨져 있으면(카드를 바꿔 꽂았다 등) 목록에서 빼고, 깨진 것은 지운다 —
>   다음 이름표 때 다시 받는다.

1. 줄(`SndItem`)이 지금은 (폴더, 번호) 둘이다. 이름 소리를 위해 **키 하나를 담을 칸**을 더한다
   (`char key[9]` — 비어 있으면 지금처럼 `/%02d/%03d.wav`, 차 있으면 `/09/<key>.wav`).
2. `soundSayNote(note, points)` → `soundSayNote(note, points, nameKey)` 로 늘린다.
   **읽을 것을 고르는 곳은 이 함수 하나**라는 규칙 그대로 — 줄을 비운 뒤
   `[이름] → [안내문/잔액]` 순서로 세운다. `nameKey` 가 비었거나 SD 에 없으면 이름만 건너뛴다.
3. `showNfc()`(1037) 에서 UID 로 이름표를 찾아(`rosterImgFor` 처럼 `rosterSndFor`) 키를 넘긴다.
   미등록 키링은 키가 없다 — 지금처럼 '등록되지 않은 키링' 만.
   허브가 학번(sid)으로 보낸 경우도 같은 표에서 찾는다(`rosterImgFor` 가 하는 그대로).
4. 이름과 다음 토막 사이 쉼은 지금의 `SOUND_GAP_MS`(60ms)를 그대로 쓴다. 어색하면 이름 뒤만
   조금 늘린다.
5. 시리얼:
   - `n` — 이름표에서 다음 아이의 이름 소리를 튼다(없으면 "SD 에 없음").
   - `i` — `soundReport` 에 "이름 소리 N/M 개" 를 더한다(SD 에 있는 수 / 명단의 수).

## 5단계 — 고정 토막도 같은 목소리로 (목소리 맞추기)

1. 서버가 `make_voices.sh` 의 표(01 · 02 · 03)를 **같은 TTS 로** 만들어 둔다
   (`scripts/makeFixedVoices.js` — 대본은 `make_voices.sh` 와 한 벌로 맞춘다).
2. `GET /api/talent/voice/pack` → `{ ver, files: [ "01/001", … ] }`,
   `GET /api/talent/voice/pack/01/001.wav`.
3. 기기는 SD 의 `/voice.ver` 와 서버의 `ver` 가 다르면 대기 때 하나씩 받아 바꾼다(3단계와 같은 길).
   → 목소리를 바꾸고 싶으면 서버에서 `VOICE_VER` 만 올리면 **모든 기기가 저절로** 새 목소리가 된다.
   SD 를 빼서 복사하는 일이 없어진다.
4. 맥 `make_voices.sh` 는 서버 없이 처음 SD 를 채우는 비상용으로 남긴다.

## 6단계 — 시험

1. 서버: 아이 하나 등록 → `uploads/talent-voice/` 에 파일이 생기는지, `afplay` 로 들어 본다.
   이름을 바꿔 보고 키가 바뀌는지, 옛 파일이 지워지는지.
2. 기기: 빈 SD(01·02·03 만) 로 켜서 시리얼에 `[이름소리] a1b2c3d4 받았다` 가 차례로 찍히는지.
   `i` 로 개수가 늘어나는지.
3. 태깅: 받은 아이 → 이름부터, 아직 못 받은 아이 → 지금처럼(이름 없이), 미등록 → 안내문만.
4. 받는 중에 태깅: 받기가 끊기고 태깅이 늦지 않는지. `/09/` 에 `.tmp` 가 남지 않는지(전원을 뽑아 본다).
5. 이름을 관리 화면에서 바꾸면 몇 초 안에 기기가 새 소리를 받는지(`{"state":"roster"}`).
6. 동명이인 · 외자 이름 · 받침이 어려운 이름 · 영어 이름을 들어 본다.

## 나중에 — 읽는 이름

TTS 가 이름을 틀리게 읽는 경우가 있다(예: '이름' 을 낱말로 읽기, 영어 이름).
관리 화면에 **'읽는 이름'** 칸을 하나 두고(비면 이름 그대로), 해시와 TTS 에는 그 값을 쓴다.
화면에는 여전히 진짜 이름이 뜬다. 1~4단계가 돌고 나서 실제로 틀리는 이름이 보이면 더한다.
