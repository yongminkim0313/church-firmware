# simple_v1 — 펀펀포인트 한 보드 판 · JC3248W535

`../funfunFirmware_v3` 는 보드 두 장이었다. 화면(T-RGB)이 서버와 말하고 그렸고, 리더(DevKitC)가
PN532·SD·앰프를 맡았다. T-RGB 가 밖으로 내주는 선이 I2C 둘뿐이라서 그렇게 나눴다.
**Guition JC3248W535** 에는 PN532 를 꽂을 4핀 커넥터, TF 슬롯, 스피커 앰프가 처음부터 붙어 있다.
그래서 이 판은 **보드 한 장이 두 보드의 일을 다 한다**(heartHunter 가 돌던 그 보드다).

| | 무엇 |
|---|---|
| 보드 | JC3248W535 — ESP32-S3 · 16MB flash · 8MB PSRAM(OPI) · AXS15231B QSPI 3.5" 320×480 · 정전식 터치 |
| 카드 | PN532 를 **UART(HSU)** 로 — P3 커넥터 하나로 전원까지 |
| 소리 | 보드의 TF 슬롯(SD) + NS4168 I2S 앰프 → SPK 커넥터 |
| 서버 | v3 와 같다 — `https://funfun.youthvision.co.kr` · 주주꿈교회 · 기기 이름 `fun-s1` · mDNS `funfun-s1` |

그림 코드는 v2·v3 와 같은 **240 원형 캔버스**에 그린다. 그 캔버스는 **240×360 판**의 가운데에 놓인다.
판을 4/3 배로 늘리면 320×480 화면이 꼭 찬다(`main.cpp` 의 `PanelJC`).

- **위아래 띠(2026-11-08)** — 판의 위 60 줄 · 아래 60 줄은 `frameBands` 가 채운다.
  - 홈과 대기 네 장처럼 위아래 끝이 분홍 띠인 화면은 그 띠를 이어 그린다.
    위에는 '펀펀포인트', 아래에는 띠 캐릭터 넷과 오늘 날짜를 얹는다.
  - NFC · 일괄 · 알림처럼 검은 바탕에 고리를 두른 화면은 맨 끝 줄을 그대로 늘여 깐다(검정).
  - 어느 쪽인지는 가운데 그림의 맨 윗줄 · 맨 아랫줄 가운데 점의 색으로 고른다. 그래서 그리는 쪽은 띠를 모른다.
- **면적 섞기** — 원본 세 점이 바깥 네 점이 되고, 가운데 두 점은 이웃을 1/3 · 2/3 씩 섞는다.
  예전의 가장 가까운 점 방식은 세 점마다 한 점을 겹쳐 그려 같은 1px 획이 1 또는 2 로 나와 글자가 울퉁불퉁했다.
  섞으면 획 굵기가 고르다(가장자리는 조금 부드러워진다).
- 시리얼 `p` 는 패널에 나간 그림 320×480 을 통째로 내보낸다(`<<FB 320 480>>`).

v3 에서는 받는 쪽(화면)과 두는 쪽(리더 SD)이 갈라져 이름 소리와 고정 토막 판을 받아 둘 수 없었다.
이 판은 한 보드라 **v2 처럼 다시 받아 SD 에 쓴다**(`VOICE_PACK_ENABLE 1` · `NAME_VOICE.md`).

### 고정 토막에 없는 안내문도 읽는다 (2026-11-07)

관리 화면이나 앱에서 포인트를 바꾸면 서버가 허브로 `+10P 전도/초대` 같은 알림을 보낸다.
출석을 거절할 때도 서버가 그 까닭을 글로 보낸다. 이런 글은 SD 에 미리 녹음해 둘 수 없다.
v3 까지는 이런 글이 오면 소리 없이 지나가고 시리얼에 `읽을 토막이 없다` 만 찍혔다.

이제 기기가 그 글을 서버(`POST /api/talent/voice/say`, 기기 키)에 보내고, 이름 소리와 같은 목소리(구글 TTS)로 받아 읽는다.
서버는 글을 읽기 좋은 말로 고쳐서 만든다. `+10P 전도/초대` 는 '전도, 초대, 10포인트 받았어요' 로 읽힌다.
한 번 만든 말은 서버가 파일로 들고 있어서 두 번째부터는 바로 내준다(처음 약 0.9초, 다음부터 약 0.3초).
코드는 `main.cpp` 의 `sayService` 와 `sound.cpp` 의 `soundPlayWav` 에 있다.

## 배선

화면·터치·백라이트·TF 슬롯·앰프는 보드에 붙어 있다. 밖으로 잇는 것은 둘이다.

| 무엇 | 어디에 |
|---|---|
| PN532 | **P3** (JST 1.25mm 4핀) — 3V3 → VCC · GND → GND · **IO17 → PN532 RXD · IO18 ← PN532 TXD** (엇갈려). 모듈 딥스위치는 **HSU** |
| 스피커 | **SPK** 2핀(1.25mm) — 4~8Ω · 1~2W |

- PN532 는 P4(QWIIC)에 꽂아도 된다. P3 과 같은 핀이라 둘 중 한 곳에만 꽂는다.
- USB 옆 P1(5V · IO43 · IO44)에 꽂아도 켤 때 두 자리를 차례로 두드려 찾아낸다.
- 켤 때 PN532 를 못 찾으면 빨간 화면으로 선다(v2 와 같다). 리더 없이 화면만 시험하려면 `-DPN532_OPTIONAL=1`.

| 보드 안 핀 | |
|---|---|
| 화면 QSPI | CS 45 · SCK 47 · D0~3 21·48·40·39 · 백라이트 1 |
| 터치 I2C | SDA 4 · SCL 8 · 0x3B |
| TF 슬롯 (HSPI) | CS 10 · MOSI 11 · SCK 12 · MISO 13 |
| 앰프 (I2S) | BCLK 42 · WS 2 · DIN 41 |

★ 앰프의 BCLK 와 DIN 은 자료마다 41·42 가 엇갈려 있다. 소리가 안 나면 `config.h` 에서 둘을 맞바꿔 본다.
heartHunter 가 같은 보드에서 이 순서로 앰프를 열었지만, **귀로는 아직 확인하지 못했다.**

## TF 카드

FAT32 로 포맷하고 `voices/` 의 `01` `02` `03` 을 뿌리에 복사한다(`tools/make_voices.sh` 가 만든다).
heartHunter 의 사진 폴더와 같은 카드에 있어도 된다. 이름 소리(`/09`)와 판 기록(`/voice.ver`)은 기기가 스스로 받아 쓴다.

## 굽기

```bash
cd simple_v1 && pio run -t upload    # find_port.py 가 시리얼 28:84:85:49:59:30 인 보드를 찾는다
```

ESP32-S3 보드는 USB ID 가 다 같다(303A:1001). 그래서 **시리얼(MAC)** 로 이 보드를 찾고, 못 찾으면 업로드를 멈춘다.
보드를 바꾸면 `find_port.py` 의 `BOARD_SERIAL` 한 줄을 고친다.

★ 지금 그 보드에는 **heartHunter** 가 올라가 있다. 여기에 구우면 heartHunter 가 지워진다.
NVS 는 이름이 달라 하트 기록이 남지만, 다시 heartHunter 를 쓰려면 그쪽을 다시 구워야 한다.

처음 켜면 아는 와이파이가 없어 곧바로 설정 모드가 열린다(`WIFI_USE_BUILTIN 0` — v3 와 같다).
화면의 QR 을 폰으로 찍어 와이파이를 넣는다.

| 명령 | 하는 일 |
|---|---|
